# M4-O1 ownership proof map

[Ownership.lean](../NetMechanics/Ownership.lean) implements the O1 mathematical layer of the [reviewed ownership contract](plans/2026-10-08-autonomous-ownership-contract.md), against HEAD `7dfc68a`. It is imported by [NetMechanics.lean](../NetMechanics.lean). This completes the structural O1 obligations below; Rust ownership, guest execution and O2–O4 runtime acceptance remain unfinished.

`Owners` is a dependent function of independently typed `OwnerLocal` states. `observeUnion`, indexed publication `materialize`, and the Sigma encoding in `projectAuthority` are mathematical views, not proposed shared databases. `Registry` has no payload parameter or state pointer. `Coordinator` holds temporary sealed candidates; each candidate retains its old value for the publication interval. Private constructors express issued evidence within this Lean module, not runtime cryptographic/nonforgeability guarantees. `Coordination.orderExact` certifies a staged event-order permutation independently of canonical slot order; `Witness.independent_event_order_result` checks that separation.

Trust and unfinished implementation: authentic invocation and code identity, validator/codec correctness, versioned detached-query fidelity, complete lifecycle/reference bookkeeping, physical alias exclusion, native purity/unwind safety, Wasm effect isolation, bounded resources/counters, executor exclusion/memory ordering, postpublication cleanup and crash/durable recovery require runtime evidence. `RestoreAdmission.sound` supplies local/reference validator soundness; it does not implement a codec. Timer readiness/order and retained pipeline fidelity remain the existing Services policy obligations. No infallible owner commit callback or desired atomicity axiom is used. Publication completion follows explicit swaps, event append, ticket consumption and gate release; initial unrelated-owner invariants are a stated hypothesis.

Development validation is `lake build`; all failure/repair logs, exit codes, final dependency checks and SHA-256 hashes are retained in external unit `writer-evidence`. Root owns full gates, unchanged frozen goldens, queue/progress metadata and any commit. No golden rebaseline or runtime acceptance is authorized by O1.
