# NetHack Fidelity D1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Core mechanics follow NetHack 5.0 C (16 items), with matching Lean 4 models/theorems and reference-model proptests.

**Architecture:** Pure `nethacked-core` functions take explicit dice rolls; `nethacked-sim` draws them from the world RNG; Lean models take the same rolls and theorems quantify over them; proptests compare Rust against a C-derived reference written in the test.

**Tech Stack:** Rust 1.88.0 (pinned), proptest 1.5, Lean 4.30 / Lake 5.0 (`lake build`).

**Spec:** `docs/superpowers/specs/2026-10-04-fidelity-d1-design.md`
**C reference (binding formulas + current code locations):** `docs/superpowers/specs/2026-10-04-fidelity-d1-c-reference.md` — each task names its section.

## Review Focus

1. Roll at the extreme ends (`d20 = 1` and `20`, `roll_343 = 0` and `342`, `rn2_5 = 0`) — boundary behaviour matches C (e.g. `d20 < tmp`, not `<=`). Test in each task.
2. Negative inputs where C uses signed math (AC −10, luck −13, nutrition < 0, enchantment −3) — no panics, no unsigned underflow. Test in Tasks 1, 3, 4, 5.
3. Save compatibility of new fields — `#[serde(default)]` so worlds serialized before the change still load. Test in Tasks 6 and 10.
4. Sim uses the new rolls exactly once per event (no double draws that shift seeds unexpectedly in a single action) — reviewers check call sites.
5. Lean statements faithful to Rust (same boundary operators and roll ranges). Reviewers compare side by side.
