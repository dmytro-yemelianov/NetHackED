## Source law and order

`zap.c:2514–2522` implements `zappable`; `dozap:2627–2684` supplies the command boundary. `obj.h` declares signed `schar spe`, normal wand charges at least -1 and `SPE_LIM=99`. Rust already stores `ItemRecord.enchantment:i8`, so no save-layout change is needed. Its representable -128..127 values must retain oldload roundtrips; the sign-based source routine can safely handle these values without clamping or overflow. A positive value decrements once, including127->126. Negative values do not decrement. Recharge history is independent and unchanged.

| Input | Charge RNG | Outcome | Terminal behavior |
| --- | --- | --- | --- |
| positive | none | decrement once, zappable | backfire gate, then direction/effect; charge0 survives |
| negative | none | unzappable, no decrement | `Nothing happens.` then dust, whole item removed, TIME |
| zero, roll1..120 | exactly bound121 | unzappable, stays0 | `Nothing happens.`, item retained, TIME |
| zero, roll0 | exactly bound121 | wrest, decrement to-1 | wrest message, backfire gate, direction/effect, surviving current wand dust, TIME |

A successful wrest emits exactly `You wrest one last charge from the worn-out wand.` before subsequent branch messages. The failure source string is `Nothing happens.`; the current English `Nothing happens. The wand is empty!` is a known mismatch, not an authorized compatibility exception. Dust is `Tobjnam(obj,"turn") + " to dust."`: article/name/plural agreement belongs to the reviewed retirement/naming seam. Controlled fully named singular fixtures can assert `The wand of create monster turns to dust.`; plural fixtures must assert plural verb agreement, without claiming all unknown-object appearance/localization mechanics are represented.

The source order is nohands -> capacity -> getobj -> check_unpaid -> need_dir -> zappable -> successful cursed bound100 gate -> direction/self/effect -> current-wand cleanup -> TIME. ## Lifetime boundary

`useupall` is whole-object retirement regardless of quantity: setnotworn -> freeinv (inventory refresh) -> obfree. It is distinct from decrement-one `useup`. `obfree` can retain used-up billed objects; unbilled retirement reaches dealloc_obj, stopping attached timers/light, clearing transient references and staging deletion. Source allocator/Lua storage behavior is evidence, not permission to execute Lua or port all object mechanics here.

The effect branch sets `current_wand`, calls weffects, then consumes its resulting identity. `destroy_items` explicitly clears it before a useup loop, including cases where a partial stack can remain. **Arena existence alone is insufficient.** The native terminal seam must receive an explicit surviving-or-cleared current-wand identity, then generation-check a surviving token before reborrowing. Cleared identity suppresses dust even if an item remains. An absent/recycled generation cannot be dereferenced, dusted or removed. Backfire owns its own retirement and never reaches a second dust removal.

Arena.destroy_item only removes a slot and registers artifact history. Armor reconciliation does not clear wield/quiver. The existing corpse-reference helper clears those references but also drops unpaid state, so its reuse would conceal a billing mismatch. P11a-C1-LIFE must fix the narrow represented retirement interface, gated on the accepted **P11a-P1-BILL** narrow billing contract and any required accepted billing implementation before use, with naming/timer evidence bounded within LIFE before deletion activation. C1 does not demand all economy, equipment or object families close.
